# STM32CubeMX — шпаргалка для CO2-монитора

Ниже — имена деталей на столе, потом цель файла и таблица выводов. Каждое новое имя сначала определяется, затем используется.

---

## 0. Что за детали на столе

Определение 1: STM32 (STMicroelectronics 32-bit, 32-разрядный микроконтроллер ST) — это семейство чипов, на которых крутится логика устройства: опрос датчика, часы, зуммер, отправка данных. Ученику нужно знать имя семейства, потому что даташит, пакет HAL и карта выводов привязаны именно к STM32, а не «к любой Arduino».

Определение 2: STM32F103C8T6 (STMicroelectronics STM32 F1 series, конкретная модель Cortex-M3) — это чип на плате: линейка F103, корпус с 48 выводами, 64 KB flash, 20 KB RAM, максимум 72 МГц. Если в CubeMX выбрать соседнюю модель, пины I2C и объём памяти не совпадут с платой на столе.

Определение 3: Cortex-M3 (ARM Cortex-M3, ядро ARM) — это процессорное ядро внутри F103: считает программу, ходит в память и принимает прерывания. Частота ядра на этой плате будет 72 МГц; от неё дальше считаются UART и таймер зуммера.

Определение 4: Blue Pill (Blue Pill, «синяя таблетка») — это готовая отладочная плата с STM32F103C8T6, кварцем 8 МГц и четырёхпроводным разъёмом программатора. Мы настраиваем CubeMX под эту плату, а не под Nucleo с другим кварцем и другими выводами.

Определение 5: CubeMX (STM32CubeMX, графический конфигуратор STM32) — это программа, в которой вы кликаете чип и выводы, а она пишет стартовый C-код (тактирование, шины, таймеры). Без чертежа в CubeMX вы либо копируете чужие пины, либо правите init руками и теряете правки.

Определение 6: пин (pin, вывод корпуса микросхемы) — это конкретная ножка чипа (PA2, PB6, PA9…), которую можно отдать под GPIO, I2C, UART или таймер. Распиновка устройства — это таблица «какая ножка какую работу делает»; её нельзя менять «для удобства CubeMX».

Определение 7: GPIO (General Purpose Input/Output, ввод-вывод общего назначения) — это режим пина «просто ножка»: высокий/низкий уровень, вход кнопки, не специальная шина. На этом мониторе кнопки на STM32 нет, поэтому GPIO-входы мы не разводим; пины датчиков и UART сразу отдают периферии.

Определение 8: периферия (peripheral, периферийный блок) — это железный модуль внутри STM32 рядом с ядром: I2C, USART, таймер, USB. CubeMX включает нужные блоки и вешает их на пины; лишняя периферия занимает ножки и раздувает init.

Определение 9: HAL (Hardware Abstraction Layer, слой аппаратных абстракций) — это библиотека ST: вы вызываете `HAL_UART_Transmit()`, а не пишете биты в регистры. CubeMX генерирует вызовы HAL и структуры вроде `huart1`; алгоритм «когда пищать» пишете вы.

Определение 10: SCD41 (Sensirion CO2 Humidity Temperature sensor, датчик CO2/T/RH) — это модуль NDIR на шине I2C, адрес **0x62**. Он живёт на I2C1 (PB6/PB7). Драйвер и команды измерения в этот файл не входят — CubeMX только включает контроллер I2C1.

Определение 11: JSON (JavaScript Object Notation, текстовый формат обмена данными) — это строки вида `{"co2":800}`, которые STM32 будет слать на ESP32 по UART. Сейчас JSON не пишем: сначала нужно, чтобы чип вообще печатал строку в терминал на правильной скорости.

Определение 12: ESP32 (Espressif Systems 32-bit, Wi‑Fi-микроконтроллер) — это вторая плата устройства: LCD, веб, сеть. Со стороны STM32 она видна только как UART на PA9/PA10. Драйвер экрана и прошивку ESP32 здесь не пишем.

Определение 13: Generate (Generate Code, генерация кода) — это кнопка CubeMX «создать/обновить C-файлы по чертежу». После Generate появляются `main.c`, `i2c.c`, `MX_*_Init()`. Свой алгоритм нельзя класть туда, где генератор имеет право перезаписать файл.

Определение 14: USER CODE (User Code, пользовательский код) — это участки между комментариями `USER CODE BEGIN` / `USER CODE END`. Только их Generate сохраняет. Правка `MX_I2C1_Init` вне этих зон исчезнет при следующей генерации.

Определение 15: I2C (Inter-Integrated Circuit, межсхемная шина) — это двухпроводная шина с адресами: один тактовый провод, один данные, несколько чипов. У нас две отдельные I2C, чтобы датчик CO2 и часы не делили одну пару проводов.

Определение 16: SCL (Serial Clock Line, линия тактового сигнала I2C) — это провод, по которому STM32 задаёт ритм обмена на шине. На I2C1 это **PB6**, на I2C2 — **PB10**. Без SCL датчик и часы не знают, когда читать бит на SDA.

Определение 17: SDA (Serial Data Line, линия данных I2C) — это провод, по которому ходят адрес, команды и измерения. На I2C1 это **PB7**, на I2C2 — **PB11**. SCL и SDA оба требуют внешних подтяжек к 3.3 В.

Определение 18: DS3231 (Dallas Semiconductor real-time clock, часы реального времени) — это RTC на I2C2 (PB10/PB11), адрес **0x68**, с батарейкой. STM32 читает время сам, чтобы тихие часы (22:00–07:00) работали даже без Wi‑Fi.

Определение 19: PWM (Pulse Width Modulation, широтно-импульсная модуляция) — это меандр с заданной частотой и долей «единицы» в периоде. Пассивному зуммеру нужна именно такая волна на **PA2**, а не постоянные 3.3 В.

Определение 20: TIM (Timer, аппаратный таймер) — это счётчик внутри STM32, который тикает от шины и умеет сам переключать пин. Зуммер сидит на **TIM2**, канал 3: таймер считает, пин PA2 выдаёт PWM.

Определение 21: USART (Universal Synchronous/Asynchronous Receiver/Transmitter, универсальный синхронно-асинхронный приёмопередатчик) — это блок STM32 для последовательного порта. USART1 на **PA9/PA10** — единственный канал к ESP32. Режим у нас асинхронный (без отдельного тактового провода).

Определение 22: UART (Universal Asynchronous Receiver/Transmitter, универсальный асинхронный приёмопередатчик) — это тот же последовательный порт с точки зрения проводов: только TX, RX и GND, без CLK. ESP32 подключён как UART; в CubeMX блок называется USART1 в режиме Asynchronous.

Определение 23: KY-006 (passive buzzer module, пассивный зуммер; корпус HW-508) — это пищалка, которая сама не генерирует тон: ей нужен PWM ~2 кГц на SIG. Вывод STM32: **PA2**, TIM2_CH3. На плате между пином и SIG стоит 100 Ω.

Определение 24: LCD 1602 (Liquid Crystal Display 16×2, символьный экран) — это дисплей на **ESP32** (I2C GPIO21/22), не на STM32. Пины LCD в CubeMX на F103 не настраивать.

Цель файла: настроить **STM32F103C8T6 (Blue Pill)** в CubeMX так, чтобы пины совпали с [`PLAN.md`](../PLAN.md), сгенерировать HAL-проект и понять, **куда потом писать свой код**.

Это не драйвер SCD41 и не JSON к ESP32. Здесь только «скелет» чипа: тактирование, шины, UART, PWM. Прикладной код (датчик, часы, тревога) пишется **после** Generate, в зонах `USER CODE`.

Распиновка этого устройства (не менять без явной причины):

| Что | Шина / пин |
|-----|------------|
| SCD41 | I2C1 **PB6 SCL / PB7 SDA** |
| DS3231 | I2C2 **PB10 SCL / PB11 SDA** |
| Зуммер KY-006 | **PA2**, TIM2_CH3 PWM |
| Связь с ESP32 | USART1 **PA9 TX / PA10 RX** |
| LCD 1602 | **на ESP32**, не на STM32 |
| Кнопки | **нет** |

## 1. CubeMX, CubeIDE и HAL — кто что делает

Три разных слоя. Их путают, и тогда непонятно, почему правка в `MX_I2C1_Init` исчезает после Generate.

Определение 25: CubeIDE (STM32CubeIDE, интегрированная среда ST) — это редактор + компилятор + отладчик, внутри которого встроен CubeMX. Для обучения ставьте её: один установщик закрывает чертёж, сборку и прошивку.

Определение 26: RCC (Reset and Clock Control, контроллер сброса и тактирования) — это блок, который раздаёт тактовые частоты ядру и периферии и умеет сбрасывать модули. Вручную заполнять регистры RCC не нужно: CubeMX пишет `SystemClock_Config()`. Без RCC у I2C и USART нет «тика», они молчат.

Определение 27: .ioc (IOC configuration file, файл чертежа CubeMX) — это сохранённая карта чипа: какие пины, какие частоты, какой USART. Двойной щелчок снова открывает картинку; Generate читает `.ioc`, а не ваши правки в `i2c.c` вне USER CODE.

Определение 28: MX-init (MX_*_Init, сгенерированные функции инициализации) — это функции вроде `MX_I2C1_Init()`, `MX_USART1_UART_Init()`, которые CubeMX переписывает при Generate. Свой код — после них, в USER CODE, не внутри тела init вне маркеров.

Определение 29: handle (HAL handle, дескриптор периферии) — это структура HAL (`hi2c1`, `huart1`, `htim2`), которую создал CubeMX. Вызовы `HAL_UART_Transmit(&huart1, …)` работают только с тем handle, который привязан к нужному блоку. Не путать `hi2c1` (SCD41) и `hi2c2` (DS3231).

### CubeMX — чертёж периферии

**Для чего.** Чтобы не писать вручную регистры RCC, GPIO, I2C, USART, TIM. Вы выбираете чип и пины на картинке, CubeMX выдаёт `main.c`, `i2c.c`, `.ioc`.

**Почему так.** У STM32F103 сотни регистров. HAL умеет их заполнять, но ему нужны handle и вызовы `MX_*_Init()`. Файл `.ioc` — сохранённый чертёж: его можно открыть снова и перегенерировать код.

**Зачем сейчас.** Без чертежа вы либо копируете чужой проект с чужими пинами, либо правите init руками и теряете правки при следующей генерации. Для этого монитора пины уже зафиксированы в PLAN.md — CubeMX должен повторить их один в один.

Определение 30: toolchain (toolchain, цепочка сборки) — это компилятор, линкер и make/ninja, которые из `.c` делают прошивку. CubeMX выдаёт текст; без toolchain МК его не исполняет. В CubeIDE toolchain уже внутри.

Определение 31: ELF (Executable and Linkable Format, формат исполняемого файла `.elf`) — это прошивка с адресами и отладочными символами, которую CubeIDE кладёт в чип через ST-Link. «Собрать проект» = получить `.elf`, не «нарисовать пины».

Определение 32: breakpoint (breakpoint, точка останова) — это пауза отладчика на строке C. Нужен живой канал SWD: если отладку в CubeMX выключить, ST-Link перестанет останавливать ядро.

Определение 33: ST-Link (ST-Link, программатор/отладчик ST) — это USB-адаптер, который по двум проводам SWD пишет flash и останавливает ядро. Blue Pill из коробки шьётся им, не «как Arduino по USB».

### CubeIDE — станок: редактор + компилятор + отладчик

**Для чего.** Собрать `.elf`, прошить Blue Pill через ST-Link, поставить breakpoint.

**Почему так.** CubeMX только генерирует исходники. Без toolchain (gcc + make/ninja внутри IDE) это текст, который МК не исполняет. CubeIDE = Eclipse-оболочка **плюс встроенный CubeMX**. Отдельный CubeMX нужен, если собираете в Keil или PlatformIO.

**Зачем сейчас.** Для обучения ставьте **STM32CubeIDE**. Один установщик закрывает генерацию, сборку и прошивку. Не размазывайте инструмент на этом этапе.

Определение 34: CMSIS (Cortex Microcontroller Software Interface Standard, стандарт интерфейса ядра Cortex) — это заголовки ядра и имена регистров (`I2C1->CR1`). HAL стоит над CMSIS. Пока скелет не заведётся, в регистры руками не лезем: на F103 легко разъехаться с тактированием CubeMX.

Определение 35: LL (Low Layer, низкоуровневый слой ST) — это тонкие функции к регистрам, быстрее HAL, но без тех же удобных handle. В этом проекте учебный код — только HAL. Смешение HAL и LL на одном I2C даёт тонкие баги.

### HAL — библиотека вызовов к железу

**Для чего.** Писать `HAL_I2C_Master_Transmit()`, `HAL_UART_Transmit()`, `HAL_TIM_PWM_Start()` вместо битовых масок в `I2C1->CR1`.

**Почему так.** HAL — слой ST над регистрами. Он медленнее «голых» регистров, но для комнатного монитора (опрос раз в 5 с) это не важно. CubeMX генерирует **вызовы HAL**, а не ваш алгоритм SCD41.

**Зачем сейчас.** Весь учебный код этого проекта — HAL. LL и CMSIS-регистры не трогаем, пока скелет не заведётся.

Аналогия: CubeMX = схема щитка, HAL = стандартные автоматы в щитке, CubeIDE = ключ и мультиметр. Программа «пищи, если CO2 > 1200» — это уже проводка **после** щитка.

## 2. Установка

### 2.1. STM32CubeIDE

1. Скачайте [STM32CubeIDE](https://www.st.com/en/development-tools/stm32cubeide.html).
2. Нужна бесплатная учётная запись ST.

**Для чего.** Получить среду, в которой есть CubeMX, компилятор и отладчик ST-Link.

**Почему так.** Пакеты HAL (STM32CubeF1) лежат на серверах ST и привязаны к лицензии/аккаунту. Без учётки установщик часто не отдаёт CubeF1 — а без CubeF1 нет `stm32f1xx_hal_i2c.c`.

**Зачем сейчас.** Если поставить IDE позже, вы начнёте «рисовать» пины в голове, а не в `.ioc`. Сначала инструмент, потом чертёж.

Определение 36: STM32CubeF1 (STM32Cube Firmware F1, пакет HAL/CMSIS для семейства F1) — это исходники именно для F103/F105, не для F4. Периферия F103 описана в своих заголовках; универсального «HAL на все STM32» в одном файле нет.

Определение 37: FM+ (Fast Mode Plus, ускоренный режим I2C до 1 МГц) — это опция I2C на более новых STM32. У F103 её нет: максимум типичный Fast Mode 400 кГц. Поэтому пакет CubeF1 нельзя заменить «от F4».

Определение 38: FIFO (First In, First Out, аппаратная очередь байт) — это буфер в USART у части STM32 (например F4). У USART F103 такого FIFO нет: байт нужно забирать вовремя (опрос или прерывание). Ещё одна причина ставить именно CubeF1.

### 2.2. Пакет STM32CubeF1

При первом проекте на F1 IDE предложит скачать **STM32CubeF1**. Согласитесь.

**Для чего.** Это HAL и CMSIS именно для семейства F1. У F4 другой пакет.

**Почему так.** Регистры и ограничения F103 зашиты в CubeF1: I2C без FM+, USART без FIFO как у F4. Чужой пакет даст не те заголовки и не ту карту периферии.

**Зачем сейчас.** Без пакета кнопка Generate выдаст ошибку или пустой проект. Не откладывайте загрузку «на потом» — потом вы уже будете смотреть на красные пины и думать, что сломан чип.

Определение 39: USB (Universal Serial Bus, универсальная последовательная шина) — это разъём питания/данных. На Blue Pill USB часто кривой или на клоне без USB-периферии. Прошивка этого монитора идёт по ST-Link, данные на телефон — с ESP32 по Wi‑Fi, не с USB STM32.

Определение 40: DFU (Device Firmware Upgrade, обновление прошивки по USB) — это способ шить чип через USB-загрузчик. На многих Blue Pill USB-DFU из коробки нет. Не ждите «подключил USB — появился диск»; нужен ST-Link.

Определение 41: SWD (Serial Wire Debug, двухпроводная отладка ARM) — это канал ядро ↔ программатор: данные и такт, плюс GND и питание. На F103 это пины PA13 и PA14. Blue Pill разведён под SWD.

Определение 42: Serial Wire (Serial Wire debug mode, режим SWD в CubeMX) — это выбор в SYS → Debug: «оставь PA13/PA14 отладчику». Это то же SWD, но имя пункта в CubeMX. Ставить **Serial Wire**, не JTAG и не «No Debug».

Определение 43: JTAG (Joint Test Action Group, старый многопроводный порт отладки) — это отладка на большем числе пинов (PA13–PA15, PB3, PB4). На Blue Pill разведён SWD; JTAG нам не нужен и отъест ножки.

Определение 44: SWDIO (Serial Wire Debug Input/Output, линия данных SWD) — это пин **PA13**. По нему ST-Link читает и пишет ядро. После Reset он по умолчанию — отладка; если отдать под GPIO, программатор пропадёт.

Определение 45: SWCLK (Serial Wire Clock, тактовая линия SWD) — это пин **PA14**. Без такта ST-Link не синхронизируется. Пара SWDIO+SWCLK = минимальный отладочный кабель.

### 2.3. Программатор ST-Link

Blue Pill шьётся по **SWD**, не по USB-DFU из коробки (на многих клонах USB и вовсе мёртвый).

Четыре провода:

| ST-Link | Blue Pill |
|---------|-----------|
| 3.3 V | 3.3 V (или питание с USB платы — тогда 3.3 V со ST-Link не дублировать) |
| GND | GND |
| SWDIO | SWDIO (PA13) |
| SWCLK | SWCLK (PA14) |

**Для чего.** Записать прошивку и останавливать ядро в отладчике.

**Почему так.** SWD — двухпроводной отладочный порт ARM. JTAG на F103 тоже есть, но на Blue Pill разведён именно SWD. PA13/PA14 после Reset по умолчанию — отладка; если их отдать под GPIO, ST-Link перестаёт цепляться.

**Зачем сейчас.** Пока Serial Wire не включён в CubeMX, вы можете один раз прошить «глухой» код и потерять отладку. Поэтому программатор проверяют **до** настройки I2C и UART.

Как проверить: в CubeIDE `Run` → `Debug`; в консоли ST-Link должен найти `STM32F1xx`. Если нет — сначала провода и драйвер ST-Link, не периферия.

## 3. Новый проект

### 3.1. Создать STM32 Project

`File` → `New` → `STM32 Project`.

**Для чего.** Появляется `.ioc` + папки `Core/`, `Drivers/`. Это контейнер, куда CubeMX положит init.

**Почему так.** CubeIDE отличает «STM32 Project» от обычного C-проекта: подключает плагин CubeMX, pack F1, скрипт линкера на 64 KB flash. Обычный C-проект этих крючков не имеет.

**Зачем сейчас.** Не копируйте чужой `.ioc` от Nucleo-F401. Другой чип — другие пины I2C1 и другой RCC.

Определение 46: MCU (Microcontroller Unit, микроконтроллер) — это сам чип «ядро + память + периферия». Вкладка **MCU/MPU Selector** ищет модель кремния. Неверный MCU = неверная карта пинов.

Определение 47: flash (Flash memory, энергонезависимая память программ) — это 64 KB на C8, куда кладётся `.elf`. Сосед `C6` — 32 KB: HAL + будущий код SCD41 туда может не влезть. Выбирайте C8 **до** настройки периферии.

Определение 48: AF (Alternate Function, альтернативная функция пина) — это режим, когда ножка отдана не GPIO, а блоку: PB6 = I2C1_SCL, PA2 = TIM2_CH3, PA9 = USART1_TX. Неверный чип в CubeMX = неверные AF на тех же именах пинов.

### 3.2. Выбрать именно `STM32F103C8Tx`

Вкладка **MCU/MPU Selector**, поиск: `STM32F103C8Tx`.

Расшифровка имени:

- **STM32F103** — линейка (Cortex-M3, до 72 МГц).
- **C8** — 48 выводов, **64 KB** flash, **20 KB** RAM.
- **T** — корпус LQFP.
- **6** на реальном чипе — температурный диапазон. В CubeMX часто пишут **C8Tx**: `x` = «любой суффикс корпуса/температуры», кремний тот же.

**Для чего.** Чтобы карта пинов, объём flash и RCC совпали с Blue Pill на столе.

**Почему так.** Сосед в селекторе `STM32F103C6Tx` — это **32 KB** flash. `CBT6` — 48 KB flash, другой корпус. `RET6` — 64 вывода, пины «уехали». Неверный чип = неверные AF на PB6/PB7.

**Зачем сейчас.** Сменить MCU после настройки периферии больно: CubeMX сбрасывает пины. Выберите C8Tx **до** I2C и TIM.

На плате читайте маркировку: `STM32F103C8T6`. Если чип **CKS32** / no-name — это клон; SWD часто работает, USB и уникальные ID — лотерея. Для монитора SWD достаточно.

### 3.3. Имя и папка

| Поле | Значение |
|------|----------|
| Project name | `co2_stm32` |
| Location | например `D:\Мои проекты\CO2 sensor\stm32_cube` |
| Targeted Language | **C** |
| Targeted Binary Type | **Executable** |

**Для чего.** Исполняемая прошивка на C, рядом с репозиторием устройства, не в случайном `workspace`.

**Почему так.** Язык C — нативный для HAL ST. C++ на F103 можно, но CubeMX генерирует `.c`, и линковка `extern "C"` добавит шум на учебном этапе. Executable — не static library: нужен `main` и таблица векторов.

**Зачем сейчас.** Путь с кириллицей (`Мои проекты`) CubeIDE обычно переваривает, но **пробелы и кириллица в имени проекта** ломают make чаще. Имя `co2_stm32` — латиница, без пробелов. Папку репозитория не переименовывайте ради IDE.

`Finish`. Откроется **Pinout & Configuration** — это и есть CubeMX внутри IDE.

## 4. Четыре вкладки CubeMX — карта экрана

Пока ничего не включайте. Запомните, куда ходить.

Определение 49: Pinout & Configuration (Pinout and Configuration, вкладка выводов и периферии) — это картинка чипа и дерево слева (SYS, RCC, I2C, USART, TIM). Здесь вешают AF на ножки. Частоту ядра здесь не считают.

Определение 50: Clock Configuration (Clock Configuration, вкладка тактирования) — это дерево «кварц → умножитель → шины». Скорость I2C в кГц задаётся в настройках I2C1, а 72 МГц ядра — только здесь.

Определение 51: Project Manager (Project Manager, менеджер проекта) — это имя проекта, toolchain и опции Generate (разнести init по файлам, сохранить USER CODE). Смотреть после пинов, **до** кнопки Generate.

Определение 52: AFIO (Alternate Function I/O, контроллер альтернативных функций) — это блок F103, который коммутирует «пин ↔ периферия» (например PB6 = I2C1_SCL) и умеет позже описанный remap. Частота SCL считается в дереве тактирования, не на картинке пинов — поэтому в CubeMX разные вкладки.

| Вкладка | Что там |
|---------|---------|
| **Pinout & Configuration** | Картинка чипа + дерево слева (SYS, RCC, I2C, USART, TIM) |
| **Clock Configuration** | Дерево тактирования: от кварца платы до частоты ядра и шин |
| **Project Manager** | Имя проекта, toolchain, опции Generate |
| **Tools** | Калькуляторы (для нас не обязательны) |

**Для чего.** Не искать «частоту I2C» на картинке пинов: скорость I2C — в Configuration выбранного I2C1, а 72 МГц — на вкладке Clock.

**Почему так.** Пин и тактовая частота — разные блоки кремния. CubeMX развёл это по экранам, потому что в даташите это разные главы.

**Зачем сейчас.** Если полезть сразу в I2C, не включив SYS и RCC, вы получите «красивые» пины и мёртвый отладчик / неверный baud. Порядок экранов = порядок кремния: сначала отладка и тактирование, потом периферия.

Правило этого проекта: **сначала Serial Wire и Clock 72 МГц, потом I2C/USART/TIM**. Пины LCD и кнопок на STM32 не настраивать.

## 5. SYS Serial Wire — сделать первым

Определение 53: SYS (System Core, системное ядро в дереве CubeMX) — это ветка настроек ядра: отладка, SysTick. Пункт Debug = Serial Wire включает SWD на PA13/PA14. Это **первая** галочка проекта, не «когда дойдём до отладки».

Слева **System Core** → **SYS**.

- Debug: **Serial Wire** (не JTAG, не «No Debug»).
- Пины **PA13** (SWDIO) и **PA14** (SWCLK) станут зелёными / занятыми. **Не кликайте их** под GPIO.

**Для чего.** Чтобы после прошивки ST-Link по-прежнему видел ядро. Это канал «мозг ↔ отладчик».

**Почему так.** После сброса PA13/PA14 — SWD. Если SYS = No Debug, CubeMX в `MX_GPIO_Init` может переключить их в обычный GPIO. Тогда программатор видит «Device not found», пока не сделаете connect under reset (и то не всегда на клонах). JTAG занимает ещё PB3/PB4 — на Blue Pill они часто разведены под другие нужды, и нам JTAG не нужен.

**Зачем сейчас.** Если сначала включить USB или PWM на «свободных» пинах и случайно задеть PA13/PA14, вы прошьёте плату вслепую. На Blue Pill это классика.

Как проверить: на картинке чипа PA13 = SYS_SWDIO, PA14 = SYS_SWCLK. В дереве SYS Debug = Serial Wire.

## 6. Тактирование: 8 МГц кварц → 72 МГц ядро

Blue Pill: внешний кварц **8 МГц**. Максимум F103: **72 МГц**.

Определение 54: HSE (High Speed External, внешний высокоскоростной тактовый источник) — это кварц (или генератор) на ножках OSC_IN/OSC_OUT. На Blue Pill припаян кварц **8 МГц**. USART 115200 и тон 2 кГц имеют смысл, только если CubeMX знает эту частоту.

Определение 55: HSI (High Speed Internal, внутренний RC-генератор ~8 МГц) — это тактовый источник внутри кремния, без кварца. Он гуляет от температуры. На F103 UART от HSI часто «плывёт» — ESP32 будет ловить битый JSON. Для монитора HSI не используем как источник системной частоты.

Определение 56: OSC_IN (Oscillator Input, вход кварцевого генератора) — это пин, куда заходит одна ножка кварца (на F103 обычно PD0). CubeMX занимает его, когда HSE = Crystal. Если HSE не включается — часто выбран не тот MCU.

Определение 57: OSC_OUT (Oscillator Output, выход кварцевого генератора) — это вторая ножка кварца (обычно PD1). Пара OSC_IN/OSC_OUT = корпус кварца 8 МГц на плате, не «цифровой вход тактирования».

Определение 58: BYPASS (HSE Bypass, обход встроенного генератора) — это режим «на OSC_IN уже приходит готовый прямоугольный такт», не кварц. У Blue Pill кварц, не внешний генератор. BYPASS не включать.

### 6.1. Включить HSE в RCC

Слева **System Core** → **RCC**:

- High Speed Clock (HSE) = **Crystal/Ceramic Resonator**.

**Для чего.** Сказать CubeMX: «на ножках OSC_IN/OSC_OUT стоит кварц, тактируйся от него».

**Почему так.** У F103 три источника системной частоты: HSI, HSE, PLL. HSE 8 МГц на Blue Pill припаян штатно. Режим BYPASS — это внешний генератор, его у нас нет.

**Зачем сейчас.** Пока HSE выключен, вкладка Clock не даст PLL от кварца. Не настраивайте USART «на глаз» до RCC: baud посчитается от неверной шины.

Как проверить: OSC_IN / OSC_OUT на картинке заняты (обычно PD0/PD1 на F103). Если HSE не включается — выбран не тот MCU.

Определение 59: PLL (Phase-Locked Loop, петля фазовой автоподстройки) — это блок-умножитель тактовой частоты внутри STM32. Он сравнивает фазу входного такта (кварц HSE 8 МГц) с фазой своего выхода и держит выход стабильно кратным входу; на Blue Pill штатно 8 МГц × 9 = 72 МГц для ядра. Без PLL ядро сидело бы на 8 МГц, UART 115200 и тон зуммера посчитались бы неверно.

Определение 60: PLLMUL (PLL Multiplier, множитель PLL) — это коэффициент умножения в RCC. Для Blue Pill **×9**: 8 × 9 = 72 МГц. ×16 дало бы 128 МГц — выше datasheet, чип может греться и сбоить.

Определение 61: PLLCLK (PLL Clock, выходная частота PLL) — это уже умноженный такт (у нас 72 МГц) до коммутатора системной частоты. Его ещё нужно выбрать как источник для ядра, иначе ядро останется на сырых 8 МГц.

Определение 62: System Clock Mux (System Clock Multiplexer, коммутатор системной частоты) — это переключатель, откуда ядро берёт такт: HSI, HSE или PLLCLK. Ставим **PLLCLK**, иначе PLL считает вхолостую.

Определение 63: SYSCLK (System Clock, системная тактовая частота) — это частота на выходе коммутатора, «главные часы» чипа. На этой плате SYSCLK = 72 МГц (выход PLL). От SYSCLK дальше делятся HCLK и шины периферии.

Определение 64: AHB (Advanced High-performance Bus, высокопроизводительная системная шина) — это внутренняя магистраль ядра, памяти и GPIO. По ней CPU ходит в flash и SRAM. Частота этой шины на F103 не выше 72 МГц.

Определение 65: HCLK (AHB clock, тактовая частота шины AHB) — это частота AHB и ядра Cortex-M3. На F103 максимум **72 МГц**; у нас HCLK = SYSCLK = 72 МГц. `HAL_Delay` и многие примеры считают, что HCLK именно такой.

Определение 66: APB1 (Advanced Peripheral Bus 1, шина периферии 1) — это «медленная» шина F103: **потолок 36 МГц**. На ней сидят I2C1, I2C2, USART2/3, **TIM2**. Если оставить 72 МГц без делителя, CubeMX красит дерево красным — это нарушение datasheet.

Определение 67: APB2 (Advanced Peripheral Bus 2, шина периферии 2) — это «быстрая» шина F103, до **72 МГц**. На ней сидит **USART1**. Baud 115200 считается от APB2 = 72 МГц — совпадёт с ESP32, если HSE правда 8 МГц.

Определение 68: prescaler (prescaler, предделитель) — это целое число, на которое делят тактовую частоту, прежде чем она попадёт в шину или в счётчик. В Clock: APB1 Prescaler **/2** даёт 36 МГц. В таймере поле Prescaler — другое место (делитель тиков PWM). Формула железа: деление на (значение_в_регистре + 1).

### 6.2. Clock Configuration: PLL ×9 → 72 МГц

Вкладка сверху **Clock Configuration**:

| Узел | Значение | Смысл |
|------|----------|--------|
| Input frequency | **8 MHz** | То, что написано на кварце платы |
| PLL Source | **HSE** | В PLL идёт кварц, не HSI |
| PLLMUL | **×9** | 8 × 9 = **72 МГц** |
| System Clock Mux | **PLLCLK** | Ядро берёт выход PLL, не «сырые» 8 МГц |
| HCLK | **72 MHz** | AHB: ядро, память, GPIO |
| APB1 Prescaler | **/2** | APB1 = **36 MHz** (потолок F103) |
| APB2 Prescaler | **/1** | APB2 = **72 MHz** |

**Для чего.** Чтобы ядро считало быстро, UART/I2C/таймеры получили **известные** частоты, а не «как получится».

**Почему так (физика и ограничения чипа).**

- **Почему 8 МГц.** На Blue Pill стоит кварц 8 МГц. Если написать 25 МГц (как у некоторых Nucleo), PLL и baud будут враньём: USART «115200» окажется другой скоростью, I2C — другой SCL.
- **Почему PLL.** HSE даёт только 8 МГц. Ядро F103 умеет 72. PLL — умножитель в тактовом дереве. ×9 — штатная комбинация «кварц 8 → 72». ×16 дало бы 128 МГц — **выше datasheet**.
- **Почему не оставить 8 МГц без PLL.** Можно, но тогда PWM и UART считаются от 8 МГц, задержки `HAL_Delay` станут другими относительно привычных примеров, и вы потеряете запас на обработку JSON. Для монитора берём максимум, который ST гарантирует.
- **Почему APB1 = /2.** В RM0008 шина APB1 на F103 **не выше 36 МГц**. На APB1 сидят I2C1, I2C2, USART2/3, TIM2. CubeMX сам красит HCLK красным, если нарушить потолок.
- **Важная ловушка TIM2.** Если APB1 prescaler ≠ 1, **тактовая частота таймера = 2 × APB1** = 72 МГц. Поэтому в расчёте PWM ниже стоит 72 МГц, хотя «шина APB1» 36 МГц. Это не баг CubeMX, так устроен RCC F1.

USART1 сидит на **APB2** (72 МГц). Baud 115200 считается от 72 МГц — это совпадёт с ESP32, если HSE правда 8 МГц.

**Зачем сейчас.** Все последующие числа (prescaler 71, ARR 499, I2C 100 кГц, baud 115200) имеют смысл **только** при этом дереве. Настроите периферию раньше — CubeMX пересчитает, но вы не поймёте, откуда 2 кГц на зуммере. Если пропустить PLL, устройство «живёт», но UART к ESP32 расходится, а тон зуммера не тот.

Если HCLK красный — щёлкните проблемное поле: CubeMX предложит делители. Не игнорируйте красный цвет: это нарушение datasheet.

Как проверить: HCLK = 72, APB1 = 36, APB2 = 72, PLL source = HSE, MUL = ×9. Ничего красного.

## 7. Периферия по схеме устройства

Настраиваем **все** блоки в CubeMX до Generate. Порядок ниже — порядок схемы: две I2C, потом UART к ESP32, потом зуммер.

В прошивке **первым** проверяем UART (раздел 11): это самый дешёвый способ увидеть, что МК живой. CubeMX при этом уже знает про I2C и TIM — лишние init не мешают, если в `while(1)` вы их пока не трогаете.

Клик по пину на картинке **или** дерево слева. Если пин не того цвета — клик правой кнопкой, сброс, выбор нужной функции.

Определение 69: master (I2C master, ведущий на шине I2C) — это тот, кто генерирует SCL и шлёт адрес. STM32 — master на обеих шинах. Адрес 0x62/0x68 в CubeMX в поле Own Address не вводится: его кладёт HAL в момент передачи.

Определение 70: slave (I2C slave, ведомый на шине I2C) — это чип, который отвечает на свой адрес: SCD41 = 0x62, DS3231 = 0x68. STM32 в этом устройстве slave не является. Поле Own Address в CubeMX — для режима slave, нам оно не нужно.

Определение 71: Standard Mode (I2C Standard Mode, стандартный режим 100 кГц) — это скорость SCL **100 kHz**. Прощает ёмкость шлейфа и плохие контакты на макетке. При APB1 = 36 МГц CubeMX сам ставит делители контроллера I2C; вам не нужно считать их руками.

Определение 72: Fast Mode (I2C Fast Mode, быстрый режим 400 кГц) — это SCL 400 кГц. SCD41 его умеет, но на старте цель — стабильный ACK, не скорость. Менять 100 → 400 имеет смысл только после того, как 100 кГц заработал.

Определение 73: pull-up (pull-up resistor, подтягивающий резистор) — это резистор от SCL/SDA к **+3.3 V**, обычно **4.7 kΩ**. I2C — шина с открытым стоком: без подтяжки линии не поднимаются. CubeMX внутренние pull-up GPIO **не ставит**; внутренние слишком слабые для десятков сантиметров провода.

Определение 74: ACK (Acknowledge, бит подтверждения I2C) — это «я здесь»: ведомый прижимает SDA после байта. Нет ACK → HAL timeout. Сначала ищут подтяжки, питание 3.3 V и путаницу SCL/SDA, не «баг библиотеки».

### 7.1. I2C1 — SCD41 (PB6 / PB7)

Слева **Connectivity** → **I2C1** → режим **I2C**.

Пины: **PB6 = I2C1_SCL**, **PB7 = I2C1_SDA**.

Configuration:

- Speed: **Standard Mode, 100 kHz**
- Address: **7 bit** (мы master; slave-адрес в init не используется)

**Для чего.** Отдельная шина к датчику CO2. SCD41 отвечает по I2C на адресе **0x62** (это уже в драйвере, не в CubeMX). CubeMX здесь только включает контроллер I2C1 и ставит частоту SCL.

**Почему так.**

- **Почему I2C, не SPI.** Модуль SCD41 разведён под I2C (SCL/SDA). Другого штатного интерфейса у типичного модуля нет.
- **Почему I2C1, не I2C2.** На F103 I2C1 по умолчанию — PB6/PB7. Это совпадает с PLAN.md. I2C2 оставляем часам, чтобы длинный/шумный кабель к SCD41 не бил по DS3231 (две короткие шины вместо одной общей).
- **Почему именно PB6/PB7.** Это **default** AF I2C1. Remap I2C1 на PB8/PB9 мы не включаем: в PLAN.md зафиксированы PB6/PB7.
- **Почему 100 кГц, не 400.** Standard Mode прощает ёмкость шлейфа. Вам не нужно считать CCR/TRISE руками.
- **Почему 7-bit address в CubeMX «не важен».** F103 в режиме master сам кладёт адрес в DR при `HAL_I2C_Master_Transmit`. Поле Own Address — для режима slave. Мы slave не являемся.

Подтяжки **4.7 kΩ к +3.3 V** на SCL и SDA CubeMX **не ставит**. Это внешние резисторы на плате (см. PLAN.md).

**Зачем сейчас.** Без I2C1 в `.ioc` не будет `hi2c1` и `MX_I2C1_Init()`. Драйвер SCD41 некуда будет воткнуть. Если пропустить и «добавить потом», придётся снова Generate — это нормально, но тогда легко забыть Speed 100 kHz и уехать в Fast Mode на сырой макетке.

Как проверить в CubeMX: PB6/PB7 подписаны I2C1_SCL/SDA. В Parameter Settings — 100 kHz. На осциллографе после кода опроса: SCL ~100 кГц, не 400.

### 7.2. I2C2 — DS3231 (PB10 / PB11)

**Connectivity** → **I2C2** → **I2C**.

Пины: **PB10 = I2C2_SCL**, **PB11 = I2C2_SDA**. Speed: **100 kHz**.

**Для чего.** Вторая шина — часы реального времени. Нужны **тихие часы** (22:00–07:00) даже когда WiFi/ESP32 лежат. STM32 читает DS3231 сам, не спрашивая сеть.

**Почему так.**

- **Почему не вешать DS3231 на I2C1 рядом с SCD41.** Одна шина = общая ёмкость и общие глюки: SCD41 при старте измерения может удерживать SCL, RTC «отвалится» по timeout. Адреса разные (0x62 и 0x68), конфликт адресов не в этом. Конфликт — **физика одной пары проводов**. PLAN.md специально развёл две шины.
- **Почему PB10/PB11.** Это default-пины I2C2 на F103C8. Другого I2C2 remap на этой ножке корпуса нет в том же виде, что у I2C1.
- **Почему снова 100 кГц.** DS3231 спокойно работает на 100 кГц. Одинаковая скорость на обеих шинах — меньше сюрпризов в голове и в HAL-таймаутах.

Адрес **0x68** в CubeMX не вводится — он будет в вызовах HAL к `hi2c2`.

**Зачем сейчас.** Тихие часы — требование устройства, не «фаза 4». Если не включить I2C2 в первом Generate, вы начнёте писать SCD41 и UART, а потом легко занять PB10/PB11 чем-то ещё (USART3 remap и т.п.). Зафиксируйте пины часов сразу.

Как проверить: PB10/PB11 = I2C2. Не путать с USART3, который на тех же ножках умеет жить в другом режиме — в дереве должен быть I2C2, не USART3.

Определение 75: baud (baud rate, скорость в бодах) — это число символьных интервалов в секунду на UART. У нас **115200**. Обе стороны (STM32 и ESP32/адаптер) должны задать одну скорость. Она считается от APB2 = 72 МГц и HSE = 8 МГц. Ошибка в PLL = «кракозябры» в терминале.

Определение 76: 8N1 (8 data bits, No parity, 1 stop bit — 8 бит данных, без чётности, 1 стоп-бит) — это кадр UART: восемь бит полезной нагрузки, без бита чётности, один стоп. Так в [`docs/uart_protocol.md`](uart_protocol.md) и у ESP32 UART2. «115200 8N1» — полная договорённость о линии.

Определение 77: Asynchronous (asynchronous mode, асинхронный режим USART) — это обычный TTL UART: только TX и RX, без тактового провода CK. ESP32 так и подключён: PA9→GPIO16 RX, PA10←GPIO17 TX, плюс GND.

Определение 78: interrupt (interrupt, прерывание) — это сигнал периферии ядру «брось цикл, обработай событие». Байт пришёл на USART1 — CPU не обязан крутить опрос в `while(1)`. Без включённого вектора `HAL_UART_Receive_IT` молчит.

Определение 79: NVIC (Nested Vectored Interrupt Controller, вложенный векторный контроллер прерываний) — это блок Cortex-M, который принимает запросы interrupt и прыгает в обработчик. Галочка **USART1 global interrupt** в CubeMX прописывает вектор `USART1_IRQHandler` → `HAL_UART_IRQHandler`.

Определение 80: polling (polling, опрос в цикле) — это «пока не придёт байт / пока не уйдёт буфер, сидим в функции HAL». `HAL_UART_Transmit` для одной строки «STM32 boot» — нормальный polling. Приём JSON через `HAL_UART_Receive` с таймаутом **блокирует** опрос SCD41.

Определение 81: DMA (Direct Memory Access, прямой доступ к памяти) — это блок, который копирует байты UART↔RAM без CPU. На F103 полезен, но это второй слой. Сначала прерывание. DMA включите, когда IT уже принимает строку.

### 7.3. USART1 — ESP32 (PA9 / PA10)

**Connectivity** → **USART1** → **Asynchronous**.

Пины: **PA9 = USART1_TX**, **PA10 = USART1_RX**.

Parameter Settings:

| Параметр | Значение |
|----------|----------|
| Baud Rate | **115200** |
| Word Length | 8 Bits |
| Parity | None |
| Stop Bits | 1 |

Это **8N1** — как в [`docs/uart_protocol.md`](uart_protocol.md) и у ESP32 UART2.

NVIC Settings: включить **USART1 global interrupt**.

**Для чего.** Единственный канал STM32 ↔ ESP32: телеметрия JSON наружу, команды (`mute`, `beep`, `set_time`) внутрь. LCD рисует ESP32 из этих пакетов. Без UART дисплей и веб не узнают ppm.

**Почему так.**

- **Почему USART1, не USART2.** USART1 на F103 висит на **APB2 (72 МГц)** и на default-пинах **PA9/PA10**. USART2 — PA2/PA3, а **PA2 у нас уже отдан зуммеру**. Конфликт пина. USART3 — PB10/PB11, а это **I2C2 часов**. Остаётся USART1.
- **Почему Asynchronous, не Synchronous.** Нужен обычный TTL UART (TX/RX), без тактового провода CK.
- **Почему 115200.** Достаточно для короткого JSON раз в 1–5 с. Совпадает с типичным USB-UART адаптером для первого теста.
- **Почему interrupt, не только polling.** Приём JSON от ESP32 в `while(1)` через `HAL_UART_Receive` с таймаутом блокирует опрос SCD41. Прерывание USART1 кладёт байт в буфер и отпускает CPU. Без галочки NVIC `HAL_UART_Receive_IT` молчит.
- **Почему не DMA на старте.** Сначала прерывание. DMA — когда IT уже принимает строку.

**Зачем сейчас.** UART — способ доказать, что тактирование верное: если 115200 читается в терминале, HSE/PLL скорее всего не врут. Настраивать USART «после зуммера» можно, но тогда первый прогон откладывается, а ошибки clock маскируются. В CubeMX включите USART1 вместе с остальным; в коде первым вызовите Transmit.

Как проверить: PA9 TX, PA10 RX. Baud 115200. В NVIC — USART1 global interrupt галочка. После прошивки (раздел 11) — строка в терминале.

Определение 82: ARR (Auto-Reload Register, регистр автоперезагрузки / Counter Period) — это число, до которого считает таймер, затем счётчик сбрасывается. Период в тиках = **ARR + 1**. Для 2 кГц при тике 1 МГц пишем **499**, не 500.

Определение 83: CCR (Capture/Compare Register, регистр захвата/сравнения) — это порог внутри периода: пока счётчик < CCR, пин в одном состоянии, потом в другом. Для канала 3 зуммера это CCR3. Скважность ≈ CCR / (ARR+1).

Определение 84: Pulse (Pulse, поле «импульс» в CubeMX) — это человеческое имя для значения CCR в окне PWM. **Pulse 250** при периоде 500 тиков = 50 %. CubeMX запишет 250 в CCR3; сам PWM не запустит.

Определение 85: duty cycle (duty cycle, скважность) — это доля периода, которую пин проводит в «единице». 250/500 = **50 %**. У прямоугольника 50/50 максимум энергии в первой гармонике; «тише» делают Pulse меньше, частоту не трогают.

### 7.4. TIM2 CH3 — зуммер KY-006 на PA2

**Timers** → **TIM2**.

1. Clock Source: **Internal Clock**.
2. Channel 3: **PWM Generation CH3**.
3. Пин: **PA2 = TIM2_CH3**.

Parameter Settings (тон **2 кГц** при timer clock **72 МГц**):

| Поле CubeMX | Число | Что это значит |
|-------------|-------|----------------|
| Prescaler | **71** | Делитель = 71+1 = **72**. 72 МГц / 72 = **1 МГц** тиков таймера |
| Counter Period (ARR) | **499** | Период = 499+1 = **500** тиков. 1 МГц / 500 = **2 кГц** PWM |
| Pulse (CCR3) | **250** | Скважность 250/500 = **50 %** |

В коде потом:

- звук: `HAL_TIM_PWM_Start(&htim2, TIM_CHANNEL_3);`
- тишина: Pulse = 0 или `HAL_TIM_PWM_Stop`

CubeMX **не** вызывает `HAL_TIM_PWM_Start` сам — только считает PSC/ARR/CCR.

**Для чего.** Пассивный KY-006 (HW-508) сам не «пищит от 3.3 V на SIG». Ему нужна **меандр** на резонансной частоте пищалки (~2–4 кГц). PWM на PA2 — этот меандр. Тревога и warning в устройстве идут сюда; тихие часы = скважность 0.

**Почему так.**

- **Почему TIM2, не TIM1.** TIM1 — продвинутый таймер на APB2, пины другие. TIM2_CH3 на F103C8 по умолчанию выведен на **PA2**. PLAN.md зафиксировал PA2. Другой канал TIM2 (CH1 = PA0, CH2 = PA1) зуммеру не нужен.
- **Почему Internal Clock.** Таймер считает от шины APB1 (с удвоением, см. раздел 6), не от внешнего пина ETR. Нам не нужен внешний тактовый вход.
- **Почему PWM Generation, не Output Compare Toggle.** PWM сам держит заданную скважность каждый период. Для «писк 200 мс» достаточно менять CCR или Start/Stop. Toggle — другая логика, хуже для «вкл/выкл тон».
- **Почему prescaler 71, не 72.** В железе F103 формула: `Ftim = Fclock / (PSC + 1)`. Пишете 71 — делите на 72. Написать 72 значит делить на 73 — частота «поедет».
- **Почему ARR 499, не 500.** Та же формула: период = ARR+1. 500 тиков на период → в регистр **499**.
- **Почему 2 кГц.** Ухо и мембрана KY-006 хорошо слышат 2–4 кГц. 1 кГц глуше, 10 кГц резче и тише на маленькой пищалке. 2 кГц — старт; частоту можно сменить ARR, не трогая пин.
- **Почему 50 %.** Максимальная энергия в первой гармонике у прямоугольника 50/50. Для «тише» уменьшают Pulse, не частоту.
- **Зачем 100 Ω на плате.** Это не настройка CubeMX. Резистор между PA2 и SIG ограничивает ток GPIO (~единицы мА). Без него пин живёт, но при ошибке монтажа легче спалить PAD.

**Зачем сейчас.** PA2 легко случайно отдать USART2_TX. Если сначала «включить всё подряд», CubeMX предложит USART2 на PA2 — и зуммер останется без таймера. Зафиксируйте TIM2_CH3 до любых экспериментов с USART2.

Как проверить в CubeMX: PA2 = TIM2_CH3, не USART2_TX. PSC=71, ARR=499, Pulse=250. На логическом анализаторе после `HAL_TIM_PWM_Start` — 2 кГц, duty ~50 %. Если молчит — сначала Start в коде, не «не тот таймер».

## 8. Что не включать

CubeMX показывает USB, SPI, ADC, I2C3 (его на F103C8 нет), кучу TIM. Не включайте «на всякий случай»: каждый блок занимает пины и init, Generate раздует `main`.

Определение 86: USB FS (USB Full Speed, USB полной скорости 12 Мбит/с) — это USB-периферия F103 на PA11/PA12. Для монитора не нужна: прошивка — ST-Link, данные на телефон — ESP32 → Wi‑Fi.

Определение 87: USBCLK (USB Clock, тактовая частота USB 48 МГц) — это отдельная ветка RCC под USB. Включённый USB требует 48 МГц от PLL и путает дерево Clock. В этом `.ioc` USB не трогать.

### USB Device / USB FS

**Для чего нам не нужен.** Прошивка — ST-Link (SWD). Данные на телефон идут **ESP32 → WiFi**, не USB STM32.

**Почему так.** USB на F103C8 — отдельная периферия на PA11/PA12, плюс кварц должен удовлетворять USB (часто берут 48 МГц от PLL). На многих Blue Pill USB разведён криво, подтяжка D+ не та, чип — клон без USB. Для монитора это мина.

**Зачем сейчас не включать.** Включённый USB меняет тактирование (нужен 48 МГц USBCLK) и занимает PA11/PA12. Потом «просто выключить» можно, но дерево clock успеет запутать. Не трогайте USB в этом `.ioc`.

### I2C под LCD / «ещё один I2C»

**Для чего нам не нужен.** LCD 1602 сидит на **ESP32 GPIO21/22**, не на STM32. Третья I2C-шина STM32 на C8T6 физически не существует (есть только I2C1 и I2C2).

**Почему так.** Архитектура устройства: STM32 — датчики и звук, ESP32 — экран и сеть. Если повесить LCD на STM32, потеряете пины и размажете протокол: тогда ESP32 не сможет рисовать без дублирования драйвера.

**Зачем сейчас не включать.** Нечего мапить на картинке «на будущее». Свободные пины оставьте свободными.

Определение 88: EXTI (External Interrupt/Event Controller, контроллер внешних прерываний) — это блок, который будит ядро по фронту на GPIO. Кнопок на плате **нет**: mute / beep / калибровка приходят JSON-ом с веба через USART1. EXTI некуда вести в схеме.

### GPIO кнопок, EXTI

**Для чего нам не нужны.** Кнопки на плате **нет**. Mute / beep / калибровка приходят JSON-ом с веба через USART1.

**Почему так.** EXTI на свободном пине — это отдельный вектор прерывания и дребезг. Его некуда вести в схеме.

**Зачем сейчас не включать.** Случайный «GPIO_Input» на PA2 или PB6 собьёт PWM или I2C. Не кликайте «свободные» пины без строки в PLAN.md.

Определение 89: SPI (Serial Peripheral Interface, последовательный периферийный интерфейс) — это шина с тактом, MOSI/MISO и chip-select. В v1 монитора SPI на STM32 не используется. Включать «на всякий случай» незачем: займёт пины.

Определение 90: ADC (Analog-to-Digital Converter, аналого-цифровой преобразователь) — это блок, который измеряет напряжение на пине. CO2 приходит цифрой с SCD41 по I2C, не с аналогового входа. ADC в этом `.ioc` не включать.

### USART2, USART3, SPI, ADC

Не нужны в v1. USART2 конфликтует с PA2, USART3 — с I2C2.

## 9. Project Manager — до кнопки Generate

Вкладка **Project Manager**. Без этих галок вы получите либо не ту IDE, либо один километровый `main.c`, либо Generate, который сотрёт ваш код.

### 9.1. Toolchain / IDE

Toolchain: **STM32CubeIDE** (если работаете в CubeIDE).

**Для чего.** Скрипты сборки и структура папок под Eclipse-проект CubeIDE.

**Почему так.** «Makefile» и «STM32CubeIDE» — разные генераторы. Неверный toolchain = проект, который эта IDE открывает криво.

**Зачем сейчас.** Смотреть **после** пинов, **до** Generate. Сменить toolchain потом — фактически новый проект.

Определение 91: Code Generator (Code Generator, страница опций генерации) — это экран Project Manager, где задают «как резать файлы» и «сохранять ли USER CODE». Первый Generate задаёт структуру репозитория; переключение галок позже делает Git-дифф нечитаемым.

### 9.2. Code Generator: pair of files

**Code Generator**:

- [x] **Generate peripheral initialization as a pair of `.c/.h` files per peripheral**

Появятся `i2c.c` / `i2c.h`, `usart.c`, `tim.c` вместо всей инициализации в `main.c`.

**Для чего.** Читать и не бояться `main.c`. I2C-настройки ищутся в `i2c.c`, UART — в `usart.c`.

**Почему так.** CubeMX и так генерирует `MX_I2C1_Init()`; галка только **разносит** функции по файлам. Линковка та же. Без галки новичок правит 800-строчный `main.c` и не видит, где кончается автоген.

**Зачем сейчас.** Первый Generate задаёт структуру. Переключить галку позже можно, но Git-дифф станет нечитаемым (код переедет из файла в файл). Включите сразу.

Определение 92: Keep User Code (Keep User Code when re-generating, сохранять пользовательский код) — это галка генератора: текст **между** `USER CODE BEGIN/END` копировать в новый файл. Без галки (или если писать вне зон) ваш код — одноразовый. Вы нажмёте Generate не один раз.

### 9.3. Keep User Code when re-generating

- [x] **Keep User Code when re-generating**

**Для чего.** Чтобы повторный Generate не уничтожил ваш `HAL_UART_Transmit` и будущий опрос SCD41.

**Почему так.** CubeMX владеет всем **вне** маркеров `USER CODE BEGIN/END`. Галка велит генератору сохранять текст **между** маркерами.

**Зачем сейчас.** Первая привычка «писать в USER CODE» ставится здесь, не после первой потери кода.

Затем **GENERATE CODE**. Согласитесь открыть проект, если IDE спросит.

## 10. Что получилось и куда писать своё

Типичное дерево:

```
co2_stm32/
├── co2_stm32.ioc          ← снова открыть CubeMX
├── Core/Src/main.c        ← while(1), только USER CODE
├── Core/Src/i2c.c         ← MX_I2C1_Init, MX_I2C2_Init
├── Core/Src/usart.c
├── Core/Src/tim.c
├── Core/Inc/main.h
└── Drivers/STM32F1xx_HAL_Driver/
```

Правило проекта:

```c
/* USER CODE BEGIN 2 */
/* сюда — ваш код после всех MX_*_Init */
/* USER CODE END 2 */
```

**Для чего.** Отделить ваш алгоритм от чертежа CubeMX. Generate можно жать сколько угодно.

**Почему так.** Генератор ищет пары комментариев `BEGIN` / `END` с **одинаковым** именем зоны. Всё между ними копируется в новый файл. Код в `MX_I2C1_Init()` **выше** `USER CODE BEGIN` — собственность CubeMX: смена 100 кГц на 400 в `.ioc` перезапишет функцию. Правка «на скорую руку» вне зоны выглядит рабочей до следующего Generate.

**Зачем сейчас.** Первая строка UART (раздел 11) уже должна жить в зоне. Если вставить её «просто после init» без маркеров — вы потеряете её при любом изменении пина.

Где **не** писать:

- тело `MX_I2C1_Init`, `MX_USART1_UART_Init`, `SystemClock_Config` вне USER CODE;
- `main.h` куски, которые CubeMX считает своими;
- `stm32f1xx_it.c` вне своих USER CODE (обработчик USART1 уже вызвает HAL — свой RX лучше в `HAL_UART_RxCpltCallback` в `main.c` в зоне).

Как проверить: в `main.c` найдите `USER CODE BEGIN 2` — он **после** `MX_USART1_UART_Init()` и остальных init. Туда и пишите.

## 11. Первый прогон — UART, не SCD41

Порядок обучения прошивки: **сначала доказать, что МК живой**, потом датчики.

В `main.c`, зона `USER CODE BEGIN 2` (после всех `MX_*_Init`):

```c
char msg[] = "STM32 boot\r\n";
HAL_UART_Transmit(&huart1, (uint8_t *)msg, sizeof(msg) - 1, 100);
```

Разбор чисел и символов:

- `&huart1` — handle, который создал CubeMX для USART1. Не `huart2`.
- `sizeof(msg) - 1` — не слать завершающий `'\0'`; терминал его не ждёт. `-1` как раз отрезает нуль.
- `100` — таймаут HAL в мс. Для 13 байт на 115200 этого с запасом.
- `\r\n` — возврат каретки + строка: Windows-терминалы и многие USB-UART ждут оба.

**Для чего.** Проверить цепочку: HSE → 72 МГц → APB2 → USART1 → пин PA9 → провод → терминал. Если строка читается, тактирование и пины UART верные. Это фундамент JSON к ESP32.

**Почему так, а не сразу SCD41.** I2C требует подтяжек, адреса 0x62, задержек datasheet. Ошибка «timeout» не скажет, жив ли МК или мёртв датчик. UART на TX — один пин наружу. Аналогия: сначала питание щитка по индикатору, потом нагрузка.

**Зачем сейчас, до зуммера и RTC.** Одна переменная в уравнении. Если пищать и опрашивать часы сразу, «тишина» может быть PWM, I2C или clock. Сначала одна строка в терминале.

Сборка: иконка молотка (Build). Прошивка: жук (Debug) или Run.

Терминал: **115200 8N1** на USART1. Пока ESP32 не прошит — USB-UART адаптер: RX адаптера на **PA9**, GND общий. Не сажайте адаптер на 5 V TX в PA10.

Определение 93: HardFault (Hard Fault, аппаратный отказ ядра) — это стоп Cortex-M, когда обращение в память или тактирование «сломалось». Пустой терминал при живых проводах часто значит: программа не дошла до Transmit, ядро в HardFault. Первым делом вернитесь к HSE 8 МГц и PLL ×9.

Как проверить: после Reset в терминале `STM32 boot`. Кракозябры — baud или не 8 МГц в Clock. Пусто — TX/RX перепутаны, не тот USART, или программа не доходит до Transmit (часто HardFault из-за clock — вернитесь к HSE).

Прерывание USART1 на этом шаге **можно не использовать**: Transmit — polling. Галка NVIC уже стоит, чтобы не возвращаться в CubeMX, когда начнёте приём JSON.

## 12. Как менять пины позже

Определение 94: remap (pin remap, переназначение выводов) — это режим AFIO, когда блок вешают на другие ножки (I2C1 на PB8/PB9 вместо PB6/PB7). CubeMX может предложить remap «удобства ради». Для этого устройства **нет**: распиновка PLAN.md важнее.

1. Открыть `co2_stm32.ioc`.
2. Сменить режим пина / периферии (осторожно: не ломайте PLAN.md).
3. **GENERATE CODE**.
4. Свой код в USER CODE останется; `MX_*_Init` перепишутся.

**Для чего.** Единственный безопасный способ сменить AF: например, передумать по скорости I2C 100→400 кГц.

**Почему так.** `.ioc` — источник истины для init. Правка регистра в `i2c.c` руками расходится с картинкой; следующий Generate вернёт старое. Два источника правды нельзя.

**Зачем сейчас знать это.** Вы будете жать Generate ещё. Правило «не править MX_* вне USER CODE» дешевле выучить до первой потери часа работы.

Если CubeMX предлагает **remap** (I2C1 на PB8/PB9) — для этого устройства **нет**. Распиновка PLAN.md важнее «удобства разводки в CubeMX».

## 14. Типичные ошибки Blue Pill

Не стыдно попасть в таблицу: это свойства платы и CubeMX, не «вы плохо учите».

| Симптом | Вероятная причина на F103 / Blue Pill | Что проверить следующим |
|---------|--------------------------------------|-------------------------|
| ST-Link не видит МК | SYS не Serial Wire; PA13/PA14 отдали GPIO; провода SWD; клон CKS32; нет общей GND | SYS = Serial Wire; 4 провода; connect under reset |
| Generate / Clock красный | HSE не Crystal; в Clock ввели не 8 MHz; PLL не ×9; APB1 без /2 | HSE Crystal → 8 × 9 = 72, APB1 = 36 |
| В терминале мусор вместо `STM32 boot` | Baud не от 72 МГц: забыли PLL или указали 25 MHz | Clock Configuration, затем снова 115200 |
| Пустой терминал | TX/RX перепутаны; смотрите RX МК вместо TX; адаптер на 5 V | PA9 = TX МК → RX адаптера; GND |
| I2C HAL timeout | Нет подтяжек **4.7 kΩ**; SCL/SDA перепутаны; модуль без 3.3 V; Fast Mode на длинных проводах | Резисторы к 3.3 V, 100 kHz, вольтметр на VCC датчика |
| SCD41 молчит, RTC жив (или наоборот) | Путаница `hi2c1` / `hi2c2` в коде | I2C1 = PB6/7 = SCD41; I2C2 = PB10/11 = DS3231 |
| PWM молчит | Не вызван `HAL_TIM_PWM_Start`; Pulse = 0; PA2 ушёл в USART2 | Start + CCR3=250; пин TIM2_CH3 |
| Зуммер пищит сразу после Generate | Pulse 250 и вы сами вызвали Start в init | Для тишины не стартовать PWM или CCR=0 до тревоги |
| После Generate пропал код | Писали вне `USER CODE BEGIN/END` или сняли Keep User Code | Только зоны; галка Keep User Code |
| `MX_I2C1_Init` «откатился» | Правили скорость руками в `.c`, потом Generate | Скорость менять в `.ioc`, не в сгенерированном init |
| USB в дереве, PA11/PA12 заняты | Включили USB «по привычке с Discovery» | Выключить USB, не трогать clock USB |
| Не хватает flash при линковке | Выбрали C6 (32 KB) вместо C8 (64 KB) | MCU = STM32F103**C8**Tx |

## Определения

Полный список по порядку номеров (дубликат блоков из текста, чтобы листать).

Определение 1: STM32 (STMicroelectronics 32-bit, 32-разрядный микроконтроллер ST) — это семейство чипов, на которых крутится логика устройства: опрос датчика, часы, зуммер, отправка данных. Ученику нужно знать имя семейства, потому что даташит, пакет HAL и карта выводов привязаны именно к STM32, а не «к любой Arduino».

Определение 2: STM32F103C8T6 (STMicroelectronics STM32 F1 series, конкретная модель Cortex-M3) — это чип на плате: линейка F103, корпус с 48 выводами, 64 KB flash, 20 KB RAM, максимум 72 МГц. Если в CubeMX выбрать соседнюю модель, пины I2C и объём памяти не совпадут с платой на столе.

Определение 3: Cortex-M3 (ARM Cortex-M3, ядро ARM) — это процессорное ядро внутри F103: считает программу, ходит в память и принимает прерывания. Частота ядра на этой плате будет 72 МГц; от неё дальше считаются UART и таймер зуммера.

Определение 4: Blue Pill (Blue Pill, «синяя таблетка») — это готовая отладочная плата с STM32F103C8T6, кварцем 8 МГц и четырёхпроводным разъёмом программатора. Мы настраиваем CubeMX под эту плату, а не под Nucleo с другим кварцем и другими выводами.

Определение 5: CubeMX (STM32CubeMX, графический конфигуратор STM32) — это программа, в которой вы кликаете чип и выводы, а она пишет стартовый C-код (тактирование, шины, таймеры). Без чертежа в CubeMX вы либо копируете чужие пины, либо правите init руками и теряете правки.

Определение 6: пин (pin, вывод корпуса микросхемы) — это конкретная ножка чипа (PA2, PB6, PA9…), которую можно отдать под GPIO, I2C, UART или таймер. Распиновка устройства — это таблица «какая ножка какую работу делает»; её нельзя менять «для удобства CubeMX».

Определение 7: GPIO (General Purpose Input/Output, ввод-вывод общего назначения) — это режим пина «просто ножка»: высокий/низкий уровень, вход кнопки, не специальная шина. На этом мониторе кнопки на STM32 нет, поэтому GPIO-входы мы не разводим; пины датчиков и UART сразу отдают периферии.

Определение 8: периферия (peripheral, периферийный блок) — это железный модуль внутри STM32 рядом с ядром: I2C, USART, таймер, USB. CubeMX включает нужные блоки и вешает их на пины; лишняя периферия занимает ножки и раздувает init.

Определение 9: HAL (Hardware Abstraction Layer, слой аппаратных абстракций) — это библиотека ST: вы вызываете `HAL_UART_Transmit()`, а не пишете биты в регистры. CubeMX генерирует вызовы HAL и структуры вроде `huart1`; алгоритм «когда пищать» пишете вы.

Определение 10: SCD41 (Sensirion CO2 Humidity Temperature sensor, датчик CO2/T/RH) — это модуль NDIR на шине I2C, адрес **0x62**. Он живёт на I2C1 (PB6/PB7). Драйвер и команды измерения в этот файл не входят — CubeMX только включает контроллер I2C1.

Определение 11: JSON (JavaScript Object Notation, текстовый формат обмена данными) — это строки вида `{"co2":800}`, которые STM32 будет слать на ESP32 по UART. Сейчас JSON не пишем: сначала нужно, чтобы чип вообще печатал строку в терминал на правильной скорости.

Определение 12: ESP32 (Espressif Systems 32-bit, Wi‑Fi-микроконтроллер) — это вторая плата устройства: LCD, веб, сеть. Со стороны STM32 она видна только как UART на PA9/PA10. Драйвер экрана и прошивку ESP32 здесь не пишем.

Определение 13: Generate (Generate Code, генерация кода) — это кнопка CubeMX «создать/обновить C-файлы по чертежу». После Generate появляются `main.c`, `i2c.c`, `MX_*_Init()`. Свой алгоритм нельзя класть туда, где генератор имеет право перезаписать файл.

Определение 14: USER CODE (User Code, пользовательский код) — это участки между комментариями `USER CODE BEGIN` / `USER CODE END`. Только их Generate сохраняет. Правка `MX_I2C1_Init` вне этих зон исчезнет при следующей генерации.

Определение 15: I2C (Inter-Integrated Circuit, межсхемная шина) — это двухпроводная шина с адресами: один тактовый провод, один данные, несколько чипов. У нас две отдельные I2C, чтобы датчик CO2 и часы не делили одну пару проводов.

Определение 16: SCL (Serial Clock Line, линия тактового сигнала I2C) — это провод, по которому STM32 задаёт ритм обмена на шине. На I2C1 это **PB6**, на I2C2 — **PB10**. Без SCL датчик и часы не знают, когда читать бит на SDA.

Определение 17: SDA (Serial Data Line, линия данных I2C) — это провод, по которому ходят адрес, команды и измерения. На I2C1 это **PB7**, на I2C2 — **PB11**. SCL и SDA оба требуют внешних подтяжек к 3.3 В.

Определение 18: DS3231 (Dallas Semiconductor real-time clock, часы реального времени) — это RTC на I2C2 (PB10/PB11), адрес **0x68**, с батарейкой. STM32 читает время сам, чтобы тихие часы (22:00–07:00) работали даже без Wi‑Fi.

Определение 19: PWM (Pulse Width Modulation, широтно-импульсная модуляция) — это меандр с заданной частотой и долей «единицы» в периоде. Пассивному зуммеру нужна именно такая волна на **PA2**, а не постоянные 3.3 В.

Определение 20: TIM (Timer, аппаратный таймер) — это счётчик внутри STM32, который тикает от шины и умеет сам переключать пин. Зуммер сидит на **TIM2**, канал 3: таймер считает, пин PA2 выдаёт PWM.

Определение 21: USART (Universal Synchronous/Asynchronous Receiver/Transmitter, универсальный синхронно-асинхронный приёмопередатчик) — это блок STM32 для последовательного порта. USART1 на **PA9/PA10** — единственный канал к ESP32. Режим у нас асинхронный (без отдельного тактового провода).

Определение 22: UART (Universal Asynchronous Receiver/Transmitter, универсальный асинхронный приёмопередатчик) — это тот же последовательный порт с точки зрения проводов: только TX, RX и GND, без CLK. ESP32 подключён как UART; в CubeMX блок называется USART1 в режиме Asynchronous.

Определение 23: KY-006 (passive buzzer module, пассивный зуммер; корпус HW-508) — это пищалка, которая сама не генерирует тон: ей нужен PWM ~2 кГц на SIG. Вывод STM32: **PA2**, TIM2_CH3. На плате между пином и SIG стоит 100 Ω.

Определение 24: LCD 1602 (Liquid Crystal Display 16×2, символьный экран) — это дисплей на **ESP32** (I2C GPIO21/22), не на STM32. Пины LCD в CubeMX на F103 не настраивать.

Определение 25: CubeIDE (STM32CubeIDE, интегрированная среда ST) — это редактор + компилятор + отладчик, внутри которого встроен CubeMX. Для обучения ставьте её: один установщик закрывает чертёж, сборку и прошивку.

Определение 26: RCC (Reset and Clock Control, контроллер сброса и тактирования) — это блок, который раздаёт тактовые частоты ядру и периферии и умеет сбрасывать модули. Вручную заполнять регистры RCC не нужно: CubeMX пишет `SystemClock_Config()`. Без RCC у I2C и USART нет «тика», они молчат.

Определение 27: .ioc (IOC configuration file, файл чертежа CubeMX) — это сохранённая карта чипа: какие пины, какие частоты, какой USART. Двойной щелчок снова открывает картинку; Generate читает `.ioc`, а не ваши правки в `i2c.c` вне USER CODE.

Определение 28: MX-init (MX_*_Init, сгенерированные функции инициализации) — это функции вроде `MX_I2C1_Init()`, `MX_USART1_UART_Init()`, которые CubeMX переписывает при Generate. Свой код — после них, в USER CODE, не внутри тела init вне маркеров.

Определение 29: handle (HAL handle, дескриптор периферии) — это структура HAL (`hi2c1`, `huart1`, `htim2`), которую создал CubeMX. Вызовы `HAL_UART_Transmit(&huart1, …)` работают только с тем handle, который привязан к нужному блоку. Не путать `hi2c1` (SCD41) и `hi2c2` (DS3231).

Определение 30: toolchain (toolchain, цепочка сборки) — это компилятор, линкер и make/ninja, которые из `.c` делают прошивку. CubeMX выдаёт текст; без toolchain МК его не исполняет. В CubeIDE toolchain уже внутри.

Определение 31: ELF (Executable and Linkable Format, формат исполняемого файла `.elf`) — это прошивка с адресами и отладочными символами, которую CubeIDE кладёт в чип через ST-Link. «Собрать проект» = получить `.elf`, не «нарисовать пины».

Определение 32: breakpoint (breakpoint, точка останова) — это пауза отладчика на строке C. Нужен живой канал SWD: если отладку в CubeMX выключить, ST-Link перестанет останавливать ядро.

Определение 33: ST-Link (ST-Link, программатор/отладчик ST) — это USB-адаптер, который по двум проводам SWD пишет flash и останавливает ядро. Blue Pill из коробки шьётся им, не «как Arduino по USB».

Определение 34: CMSIS (Cortex Microcontroller Software Interface Standard, стандарт интерфейса ядра Cortex) — это заголовки ядра и имена регистров (`I2C1->CR1`). HAL стоит над CMSIS. Пока скелет не заведётся, в регистры руками не лезем: на F103 легко разъехаться с тактированием CubeMX.

Определение 35: LL (Low Layer, низкоуровневый слой ST) — это тонкие функции к регистрам, быстрее HAL, но без тех же удобных handle. В этом проекте учебный код — только HAL. Смешение HAL и LL на одном I2C даёт тонкие баги.

Определение 36: STM32CubeF1 (STM32Cube Firmware F1, пакет HAL/CMSIS для семейства F1) — это исходники именно для F103/F105, не для F4. Периферия F103 описана в своих заголовках; универсального «HAL на все STM32» в одном файле нет.

Определение 37: FM+ (Fast Mode Plus, ускоренный режим I2C до 1 МГц) — это опция I2C на более новых STM32. У F103 её нет: максимум типичный Fast Mode 400 кГц. Поэтому пакет CubeF1 нельзя заменить «от F4».

Определение 38: FIFO (First In, First Out, аппаратная очередь байт) — это буфер в USART у части STM32 (например F4). У USART F103 такого FIFO нет: байт нужно забирать вовремя (опрос или прерывание). Ещё одна причина ставить именно CubeF1.

Определение 39: USB (Universal Serial Bus, универсальная последовательная шина) — это разъём питания/данных. На Blue Pill USB часто кривой или на клоне без USB-периферии. Прошивка этого монитора идёт по ST-Link, данные на телефон — с ESP32 по Wi‑Fi, не с USB STM32.

Определение 40: DFU (Device Firmware Upgrade, обновление прошивки по USB) — это способ шить чип через USB-загрузчик. На многих Blue Pill USB-DFU из коробки нет. Не ждите «подключил USB — появился диск»; нужен ST-Link.

Определение 41: SWD (Serial Wire Debug, двухпроводная отладка ARM) — это канал ядро ↔ программатор: данные и такт, плюс GND и питание. На F103 это пины PA13 и PA14. Blue Pill разведён под SWD.

Определение 42: Serial Wire (Serial Wire debug mode, режим SWD в CubeMX) — это выбор в SYS → Debug: «оставь PA13/PA14 отладчику». Это то же SWD, но имя пункта в CubeMX. Ставить **Serial Wire**, не JTAG и не «No Debug».

Определение 43: JTAG (Joint Test Action Group, старый многопроводный порт отладки) — это отладка на большем числе пинов (PA13–PA15, PB3, PB4). На Blue Pill разведён SWD; JTAG нам не нужен и отъест ножки.

Определение 44: SWDIO (Serial Wire Debug Input/Output, линия данных SWD) — это пин **PA13**. По нему ST-Link читает и пишет ядро. После Reset он по умолчанию — отладка; если отдать под GPIO, программатор пропадёт.

Определение 45: SWCLK (Serial Wire Clock, тактовая линия SWD) — это пин **PA14**. Без такта ST-Link не синхронизируется. Пара SWDIO+SWCLK = минимальный отладочный кабель.

Определение 46: MCU (Microcontroller Unit, микроконтроллер) — это сам чип «ядро + память + периферия». Вкладка **MCU/MPU Selector** ищет модель кремния. Неверный MCU = неверная карта пинов.

Определение 47: flash (Flash memory, энергонезависимая память программ) — это 64 KB на C8, куда кладётся `.elf`. Сосед `C6` — 32 KB: HAL + будущий код SCD41 туда может не влезть. Выбирайте C8 **до** настройки периферии.

Определение 48: AF (Alternate Function, альтернативная функция пина) — это режим, когда ножка отдана не GPIO, а блоку: PB6 = I2C1_SCL, PA2 = TIM2_CH3, PA9 = USART1_TX. Неверный чип в CubeMX = неверные AF на тех же именах пинов.

Определение 49: Pinout & Configuration (Pinout and Configuration, вкладка выводов и периферии) — это картинка чипа и дерево слева (SYS, RCC, I2C, USART, TIM). Здесь вешают AF на ножки. Частоту ядра здесь не считают.

Определение 50: Clock Configuration (Clock Configuration, вкладка тактирования) — это дерево «кварц → умножитель → шины». Скорость I2C в кГц задаётся в настройках I2C1, а 72 МГц ядра — только здесь.

Определение 51: Project Manager (Project Manager, менеджер проекта) — это имя проекта, toolchain и опции Generate (разнести init по файлам, сохранить USER CODE). Смотреть после пинов, **до** кнопки Generate.

Определение 52: AFIO (Alternate Function I/O, контроллер альтернативных функций) — это блок F103, который коммутирует «пин ↔ периферия» (например PB6 = I2C1_SCL) и умеет позже описанный remap. Частота SCL считается в дереве тактирования, не на картинке пинов — поэтому в CubeMX разные вкладки.

Определение 53: SYS (System Core, системное ядро в дереве CubeMX) — это ветка настроек ядра: отладка, SysTick. Пункт Debug = Serial Wire включает SWD на PA13/PA14. Это **первая** галочка проекта, не «когда дойдём до отладки».

Определение 54: HSE (High Speed External, внешний высокоскоростной тактовый источник) — это кварц (или генератор) на ножках OSC_IN/OSC_OUT. На Blue Pill припаян кварц **8 МГц**. USART 115200 и тон 2 кГц имеют смысл, только если CubeMX знает эту частоту.

Определение 55: HSI (High Speed Internal, внутренний RC-генератор ~8 МГц) — это тактовый источник внутри кремния, без кварца. Он гуляет от температуры. На F103 UART от HSI часто «плывёт» — ESP32 будет ловить битый JSON. Для монитора HSI не используем как источник системной частоты.

Определение 56: OSC_IN (Oscillator Input, вход кварцевого генератора) — это пин, куда заходит одна ножка кварца (на F103 обычно PD0). CubeMX занимает его, когда HSE = Crystal. Если HSE не включается — часто выбран не тот MCU.

Определение 57: OSC_OUT (Oscillator Output, выход кварцевого генератора) — это вторая ножка кварца (обычно PD1). Пара OSC_IN/OSC_OUT = корпус кварца 8 МГц на плате, не «цифровой вход тактирования».

Определение 58: BYPASS (HSE Bypass, обход встроенного генератора) — это режим «на OSC_IN уже приходит готовый прямоугольный такт», не кварц. У Blue Pill кварц, не внешний генератор. BYPASS не включать.

Определение 59: PLL (Phase-Locked Loop, петля фазовой автоподстройки) — это блок-умножитель тактовой частоты внутри STM32. Он сравнивает фазу входного такта (кварц HSE 8 МГц) с фазой своего выхода и держит выход стабильно кратным входу; на Blue Pill штатно 8 МГц × 9 = 72 МГц для ядра. Без PLL ядро сидело бы на 8 МГц, UART 115200 и тон зуммера посчитались бы неверно.

Определение 60: PLLMUL (PLL Multiplier, множитель PLL) — это коэффициент умножения в RCC. Для Blue Pill **×9**: 8 × 9 = 72 МГц. ×16 дало бы 128 МГц — выше datasheet, чип может греться и сбоить.

Определение 61: PLLCLK (PLL Clock, выходная частота PLL) — это уже умноженный такт (у нас 72 МГц) до коммутатора системной частоты. Его ещё нужно выбрать как источник для ядра, иначе ядро останется на сырых 8 МГц.

Определение 62: System Clock Mux (System Clock Multiplexer, коммутатор системной частоты) — это переключатель, откуда ядро берёт такт: HSI, HSE или PLLCLK. Ставим **PLLCLK**, иначе PLL считает вхолостую.

Определение 63: SYSCLK (System Clock, системная тактовая частота) — это частота на выходе коммутатора, «главные часы» чипа. На этой плате SYSCLK = 72 МГц (выход PLL). От SYSCLK дальше делятся HCLK и шины периферии.

Определение 64: AHB (Advanced High-performance Bus, высокопроизводительная системная шина) — это внутренняя магистраль ядра, памяти и GPIO. По ней CPU ходит в flash и SRAM. Частота этой шины на F103 не выше 72 МГц.

Определение 65: HCLK (AHB clock, тактовая частота шины AHB) — это частота AHB и ядра Cortex-M3. На F103 максимум **72 МГц**; у нас HCLK = SYSCLK = 72 МГц. `HAL_Delay` и многие примеры считают, что HCLK именно такой.

Определение 66: APB1 (Advanced Peripheral Bus 1, шина периферии 1) — это «медленная» шина F103: **потолок 36 МГц**. На ней сидят I2C1, I2C2, USART2/3, **TIM2**. Если оставить 72 МГц без делителя, CubeMX красит дерево красным — это нарушение datasheet.

Определение 67: APB2 (Advanced Peripheral Bus 2, шина периферии 2) — это «быстрая» шина F103, до **72 МГц**. На ней сидит **USART1**. Baud 115200 считается от APB2 = 72 МГц — совпадёт с ESP32, если HSE правда 8 МГц.

Определение 68: prescaler (prescaler, предделитель) — это целое число, на которое делят тактовую частоту, прежде чем она попадёт в шину или в счётчик. В Clock: APB1 Prescaler **/2** даёт 36 МГц. В таймере поле Prescaler — другое место (делитель тиков PWM). Формула железа: деление на (значение_в_регистре + 1).

Определение 69: master (I2C master, ведущий на шине I2C) — это тот, кто генерирует SCL и шлёт адрес. STM32 — master на обеих шинах. Адрес 0x62/0x68 в CubeMX в поле Own Address не вводится: его кладёт HAL в момент передачи.

Определение 70: slave (I2C slave, ведомый на шине I2C) — это чип, который отвечает на свой адрес: SCD41 = 0x62, DS3231 = 0x68. STM32 в этом устройстве slave не является. Поле Own Address в CubeMX — для режима slave, нам оно не нужно.

Определение 71: Standard Mode (I2C Standard Mode, стандартный режим 100 кГц) — это скорость SCL **100 kHz**. Прощает ёмкость шлейфа и плохие контакты на макетке. При APB1 = 36 МГц CubeMX сам ставит делители контроллера I2C; вам не нужно считать их руками.

Определение 72: Fast Mode (I2C Fast Mode, быстрый режим 400 кГц) — это SCL 400 кГц. SCD41 его умеет, но на старте цель — стабильный ACK, не скорость. Менять 100 → 400 имеет смысл только после того, как 100 кГц заработал.

Определение 73: pull-up (pull-up resistor, подтягивающий резистор) — это резистор от SCL/SDA к **+3.3 V**, обычно **4.7 kΩ**. I2C — шина с открытым стоком: без подтяжки линии не поднимаются. CubeMX внутренние pull-up GPIO **не ставит**; внутренние слишком слабые для десятков сантиметров провода.

Определение 74: ACK (Acknowledge, бит подтверждения I2C) — это «я здесь»: ведомый прижимает SDA после байта. Нет ACK → HAL timeout. Сначала ищут подтяжки, питание 3.3 V и путаницу SCL/SDA, не «баг библиотеки».

Определение 75: baud (baud rate, скорость в бодах) — это число символьных интервалов в секунду на UART. У нас **115200**. Обе стороны (STM32 и ESP32/адаптер) должны задать одну скорость. Она считается от APB2 = 72 МГц и HSE = 8 МГц. Ошибка в PLL = «кракозябры» в терминале.

Определение 76: 8N1 (8 data bits, No parity, 1 stop bit — 8 бит данных, без чётности, 1 стоп-бит) — это кадр UART: восемь бит полезной нагрузки, без бита чётности, один стоп. Так в [`docs/uart_protocol.md`](uart_protocol.md) и у ESP32 UART2. «115200 8N1» — полная договорённость о линии.

Определение 77: Asynchronous (asynchronous mode, асинхронный режим USART) — это обычный TTL UART: только TX и RX, без тактового провода CK. ESP32 так и подключён: PA9→GPIO16 RX, PA10←GPIO17 TX, плюс GND.

Определение 78: interrupt (interrupt, прерывание) — это сигнал периферии ядру «брось цикл, обработай событие». Байт пришёл на USART1 — CPU не обязан крутить опрос в `while(1)`. Без включённого вектора `HAL_UART_Receive_IT` молчит.

Определение 79: NVIC (Nested Vectored Interrupt Controller, вложенный векторный контроллер прерываний) — это блок Cortex-M, который принимает запросы interrupt и прыгает в обработчик. Галочка **USART1 global interrupt** в CubeMX прописывает вектор `USART1_IRQHandler` → `HAL_UART_IRQHandler`.

Определение 80: polling (polling, опрос в цикле) — это «пока не придёт байт / пока не уйдёт буфер, сидим в функции HAL». `HAL_UART_Transmit` для одной строки «STM32 boot» — нормальный polling. Приём JSON через `HAL_UART_Receive` с таймаутом **блокирует** опрос SCD41.

Определение 81: DMA (Direct Memory Access, прямой доступ к памяти) — это блок, который копирует байты UART↔RAM без CPU. На F103 полезен, но это второй слой. Сначала прерывание. DMA включите, когда IT уже принимает строку.

Определение 82: ARR (Auto-Reload Register, регистр автоперезагрузки / Counter Period) — это число, до которого считает таймер, затем счётчик сбрасывается. Период в тиках = **ARR + 1**. Для 2 кГц при тике 1 МГц пишем **499**, не 500.

Определение 83: CCR (Capture/Compare Register, регистр захвата/сравнения) — это порог внутри периода: пока счётчик < CCR, пин в одном состоянии, потом в другом. Для канала 3 зуммера это CCR3. Скважность ≈ CCR / (ARR+1).

Определение 84: Pulse (Pulse, поле «импульс» в CubeMX) — это человеческое имя для значения CCR в окне PWM. **Pulse 250** при периоде 500 тиков = 50 %. CubeMX запишет 250 в CCR3; сам PWM не запустит.

Определение 85: duty cycle (duty cycle, скважность) — это доля периода, которую пин проводит в «единице». 250/500 = **50 %**. У прямоугольника 50/50 максимум энергии в первой гармонике; «тише» делают Pulse меньше, частоту не трогают.

Определение 86: USB FS (USB Full Speed, USB полной скорости 12 Мбит/с) — это USB-периферия F103 на PA11/PA12. Для монитора не нужна: прошивка — ST-Link, данные на телефон — ESP32 → Wi‑Fi.

Определение 87: USBCLK (USB Clock, тактовая частота USB 48 МГц) — это отдельная ветка RCC под USB. Включённый USB требует 48 МГц от PLL и путает дерево Clock. В этом `.ioc` USB не трогать.

Определение 88: EXTI (External Interrupt/Event Controller, контроллер внешних прерываний) — это блок, который будит ядро по фронту на GPIO. Кнопок на плате **нет**: mute / beep / калибровка приходят JSON-ом с веба через USART1. EXTI некуда вести в схеме.

Определение 89: SPI (Serial Peripheral Interface, последовательный периферийный интерфейс) — это шина с тактом, MOSI/MISO и chip-select. В v1 монитора SPI на STM32 не используется. Включать «на всякий случай» незачем: займёт пины.

Определение 90: ADC (Analog-to-Digital Converter, аналого-цифровой преобразователь) — это блок, который измеряет напряжение на пине. CO2 приходит цифрой с SCD41 по I2C, не с аналогового входа. ADC в этом `.ioc` не включать.

Определение 91: Code Generator (Code Generator, страница опций генерации) — это экран Project Manager, где задают «как резать файлы» и «сохранять ли USER CODE». Первый Generate задаёт структуру репозитория; переключение галок позже делает Git-дифф нечитаемым.

Определение 92: Keep User Code (Keep User Code when re-generating, сохранять пользовательский код) — это галка генератора: текст **между** `USER CODE BEGIN/END` копировать в новый файл. Без галки (или если писать вне зон) ваш код — одноразовый. Вы нажмёте Generate не один раз.

Определение 93: HardFault (Hard Fault, аппаратный отказ ядра) — это стоп Cortex-M, когда обращение в память или тактирование «сломалось». Пустой терминал при живых проводах часто значит: программа не дошла до Transmit, ядро в HardFault. Первым делом вернитесь к HSE 8 МГц и PLL ×9.

Определение 94: remap (pin remap, переназначение выводов) — это режим AFIO, когда блок вешают на другие ножки (I2C1 на PB8/PB9 вместо PB6/PB7). CubeMX может предложить remap «удобства ради». Для этого устройства **нет**: распиновка PLAN.md важнее.
