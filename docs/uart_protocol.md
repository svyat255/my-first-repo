# UART протокол STM32 ↔ ESP32

## Общие правила

- Интерфейс: STM32 USART1 (PA9/PA10) ↔ ESP32 GPIO16/17 и GPIO25/26, **115200** baud, 8N1.
- Формат: одна JSON-строка на сообщение, завершается `\n` (0x0A).
- Кодировка: ASCII.
- Максимальная длина строки: 256 байт.

ESP32 использует телеметрию STM32 для **LCD 1602**.

## STM32 → ESP32 (телеметрия)

Каждые 5 s или при смене уровня тревоги.

```json
{"co2":845,"temp":23.1,"rh":45,"alert":1,"quiet":false,"time":"22:15"}
```

| Поле | Тип | Описание |
|------|-----|----------|
| `co2` | int | CO2, ppm (SCD41 NDIR) |
| `temp` | float | Температура, °C |
| `rh` | int | Относительная влажность, % |
| `alert` | int | 0 = normal, 1 = warning, 2 = alarm |
| `quiet` | bool | Тихие часы или mute — звук выключен |
| `time` | string | Локальное время HH:MM с DS3231 |

## ESP32 → STM32 (время, настройки, команды с веба)

При старте, при изменении настроек, раз в 60 s; команды — сразу.

Определение 1: пакет настроек (settings packet, JSON порогов без `cmd`) — одна строка ESP32 → STM32 с порогами, тихими часами, `tz` и опционально `epoch`. STM32 применяет поля, которые есть; неизвестные ключи игнорирует. Это не команда с веба.

```json
{"co2_warn":800,"co2_crit":1200,"quiet_start":22,"quiet_end":7,"tz":3,"epoch":1719320000}
```

| Поле | Тип | Описание |
|------|-----|----------|
| `co2_warn` | int | Порог warning, ppm |
| `co2_crit` | int | Порог alarm, ppm |
| `quiet_start` | int | Час начала тихих часов (0–23) |
| `quiet_end` | int | Час конца (0–23) |
| `tz` | int | Смещение часового пояса, часы относительно UTC (−12…+14) |
| `epoch` | int | Unix time UTC для DS3231; только если NTP уже синхронизирован |

Определение 2: tz (timezone offset, смещение часового пояса) — целое число часов относительно UTC (−12…+14) в пакете настроек. STM32 пишет DS3231 локальным временем (UTC + tz). На ESP32 то же значение задаёт `configTime` и форму «UTC±N».

Определение 3: epoch (Unix time, секунды с 1970-01-01 UTC) — поле **внутри пакета настроек**. Если значение > 1.7e9, STM32 ставит DS3231. Отдельная команда `{"cmd":"set_time","epoch":…}` дублирует это с веба, но при инициализации **не обязательна**: достаточно `epoch` в настройках.

### Расчёт quiet (через полночь, 22–07) — на STM32 по DS3231

```
quiet = (hour >= quiet_start) OR (hour < quiet_end)
```

## Команды ESP32 → STM32 (с HTML)

```json
{"cmd":"beep"}
{"cmd":"mute","minutes":60}
{"cmd":"unmute"}
{"cmd":"set_alerts","enabled":true}
{"cmd":"set_time","epoch":1719320000}
{"cmd":"frc_calibrate"}
```

| cmd | Действие |
|-----|----------|
| `beep` | Тест KY-006, 1 s, игнор quiet/mute |
| `mute` | Звук off на N минут |
| `unmute` | Снять mute |
| `set_alerts` | Вкл/выкл звуковых тревог |
| `set_time` | Запись epoch в DS3231 (I2C2); не нужна при старте, если epoch уже в пакете настроек |
| `frc_calibrate` | Forced Recalibration SCD41 (400 ppm) |

Строка без `"cmd"` и без полей порогов (например `{"ping":1}` с петли UART ESP32) STM32 игнорирует.

## Инициализация

1. STM32: I2C1 SCD41, I2C2 DS3231, PWM PA2, UART.
2. ESP32: I2C LCD, WiFi (неблокирующий портал), NTP.
3. ESP32 → пакет настроек с `epoch` (если NTP уже дал время) → STM32 пишет DS3231. `cmd:set_time` на этом шаге не требуется.
4. В том же пакете — пороги, quiet hours и `tz`.
5. STM32 → телеметрия каждые 5 s; ESP32 обновляет LCD и веб.

## Ошибки

- Битый JSON — пакет игнорируется.
- Нет UART от STM32 &gt; 10 s — LCD: `NO STM32 LINK`.
- Нет UART от ESP32 &gt; 120 s — STM32: DS3231 + настройки из flash; звук по тихим часам работает.

## Примеры

```
STM32: {"co2":420,"temp":22.0,"rh":48,"alert":0,"quiet":false,"time":"14:30"}
ESP:   {"co2_warn":800,"co2_crit":1200,"quiet_start":22,"quiet_end":7,"tz":3,"epoch":1719320000}
ESP:   {"cmd":"beep"}
ESP:   {"cmd":"mute","minutes":60}
STM32: {"co2":1350,"temp":24.1,"rh":52,"alert":2,"quiet":true,"time":"22:15"}
```
